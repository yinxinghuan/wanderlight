# Requirements — v2 世界扩展版

## 1. Overview

《漫游微光 / Wanderlight》是一款手机优先、持续存档的开放世界文字 RPG。玩家来到一条由月线连接的轻幻想海岸：港城、葡萄丘、雾林、潮汐群岛、夜市与成人研修院之外，还有风崖信号站、芦水渡村、白浪浴镇、旧石坑花园和云阶果园。玩家可以接工作、旅行、吃饭、休息、结识成年人，并自行决定一段关系停留在陌生、熟悉、同行、竞争或暧昧中的哪一步。

### Game Profile

- **单次体验形态**：开放式探索为主、短事件为辅。一次打开可以完成 3–8 个回合，也可以持续游玩。
- **期望投入**：首次体验约 8–15 分钟；回流玩家可在一个自然场景结束后停止。
- **跨次连续性**：持续叙事世界。地点、时间、物品、钱币、关系事件、承诺、角色去向以及角色视觉身份都保留。
- **持久状态**：完整世界存档、三项数值、地图、物品、已介绍角色、同行者、关系事件和每个长期角色的视觉身份记录。
- **自然停止点**：旅店休息、月线车厢、车站月台、完成一份工作或明确告别之后。
- **回访理由**：继续未完成的工作或旅程；寻找已经认识的人；追踪跨区域的地图、天气、种植、演出和邮路线索；看看偶遇是否会成长为稳定关系。

### 适用承诺层级

- **发现承诺**：一个比恋爱菜单更宽广的轻幻想世界；关系是探索的结果，不是唯一目标。
- **首个有效动作**：玩家在灯湾码头选择挣钱、搭车或回应一个人的邀请，并立即看到地点、资源或关系事实变化。
- **首次体验**：三个开场方向都必须成立；玩家至少经历一次自由选择、一次人物正式登场、一次获得报酬或资源取舍、一次月线中转，以及一次与前一选择相关的重逢。
- **前 10 分钟**：认识三种不同生活方式，理解人物会记得承诺与边界，并亲历“离开—中转—换地—重逢”。后续游玩会逐步发现其他地区与人物，不在开场一次性倾倒全部世界设定。
- **单次结束**：世界不强制结算；自然停止点明确说明已经保存到哪个地点和时刻。
- **长期承诺**：预设角色提供稳定深度，运行时角色可以从偶遇晋升为长期关系对象；玩家不被绑定到唯一主线或唯一攻略对象。

一句话核心玩法：**在自由旅行和谋生中选择把时间给谁，并通过可追溯的共同事件，让偶遇变成玩家真正记得的一段关系。**

## 2. Visual Design

- 使用累积阅读的响应式文字 RPG 界面，事件图片插入其对应叙事位置，不采用每步强制全屏换图。
- 视觉重心是“地方先存在，人物在其中生活”：环境建立镜头、人物身份锚点、反应镜头与月线中转镜头交替出现。
- 八名预设角色和运行时生成角色都必须拥有稳定视觉身份。未固化身份的临时 NPC 不得反复生成无参考的面部特写。
- 关系场景以距离、目光、动作、衣料、手部接触、共同劳动和空间选择表达暧昧，不依赖直白裸露或性行为。
- 主验收为 `390×844` 与 `320×568`，同时检查 `1024×768` 与 `1440×900`；外部访客栏不影响平台内主构图。
- 正式海报只允许英文 `WANDERLIGHT`，禁止中文、伪中文和生成式可读文字。
- 完整视觉系统见 `doc/visual.md`。

### 双语叙事语言

- 中文和英文都以“一遍读懂行动与因果”为底线，分别按各自自然句法创作，不做机械逐句直译。
- 质感来自具体动作、光线、声音、距离、停顿、手势、物件和人物潜台词；关键事实不得交给抽象隐喻承担。
- 每个短段主要推进一个新事实；每次最多引入一个陌生世界词，并在同句或下一句通过外形、用途或现场反应自然解释。
- 对话像当前处境中的成年人，不替作者讲世界观；选项使用直接动词，只引用已经可见的人、地点、物品或问题。
- 该标准同时约束作者预写内容与未来 AI 自由生成内容。生成正文不得出现“中转锚点、视觉身份、关系升温、剧情节点”等幕后设计语言。

## 3. Game Mechanics

### 核心循环

1. 读取当前地点、时间、可见人物、短期目标和最近关系事实。
2. 选择交谈/同行、探索/工作，或保护资源/边界；也可以输入自由行动。
3. 权威状态更新地点、时间、精力、钱币、风闻、物品或关系事件。
4. 叙事展示直接结果；图片导演在地点变化、正式登场、关系转折、任何说话者的重要对白或连续两回合无图时生成事件图。重要性由对白是否揭示关键事实、改变关系、设定边界、作出承诺/请求、警告危险、建立任务或形成明显情绪转折决定，不以人物是否属于预设主角判定。普通观察、对话、物件发现和环境事件优先使用主角第一人称视角；只有动作本身需要看见主角完整轮廓、服装或身体关系时才使用第三人称并引用玩家头像。
5. 玩家根据新事实继续行动，或在月线车厢、旅店和工作结束处自然停止。

### v2 内容边界

- **正式区域**：由原有 7 个节点扩为 12 个节点：灯湾码头、月线车厢、杯影夜市、银叶葡萄丘、雾杉林、潮汐群岛、远灯研修院、风玻璃崖、芦水渡村、白浪浴镇、旧石坑花园和云阶果园。每个区域至少有一种工作/资源活动、一种社交活动、一种地点特有事件、一种离开或休息方式，以及不会复用其他区域地标的图片语言。
- **开场三路**：帮助发光种荚进入媛夕路线；接夜班工作进入罗温路线；去夜市搬箱进入塞莱斯特路线。三路都在首回合明确人物、报酬和下一行动，不存在“假选项”。
- **八名预设长期角色**：保留媛夕、罗温、塞莱斯特三条作者级开场路线，并增加伊奥娜（风崖天气观测）、卢克（渡船与水闸修理）、诺尔（公共浴场与流动厨房）、伊登（石坑园艺与石工）和妮莎（沿线邮递）五名可在旅行中逐步遇见的预设角色。八人都拥有稳定 ID、不同活动区域、独立动机、边界和跨区域关系；新增人物在正文完成可见登场前不得出现在人物面板、目标或选项中。
- **跨区域长期线索**：至少维持五类可重复推进而不强迫玩家接取的世界线索：缺失海岸地图与信号站、月光植物迁移与果园授粉、潮汐演出与沿线集市、渡村水闸与群岛航路、以及连接各地人物的邮袋与未送达物件。每条线索必须在不同地点留下可见后果，并允许玩家中途离开后再继续。
- **地区事件轮换**：十二个正式地区各提供 `4` 个作者预设事件，共 `48` 个，覆盖当地工作机会、日常社交、环境变化、外来访客或跨区线索；每个事件都有稳定 ID、具体现场、可执行行动和地点专属图片提示。事件在玩家主动查看当地动静时触发；只有当前没有活动危险、等待回应、正在执行的工作或明确未完目标时，系统才可把一个具体事件行动作为兜底。随机事件不得自动插入并打断当前故事。
- **确定性随机与去重**：玩家看到的是轮换事件，底层按游戏、地点、日期、事件轮次和存档状态稳定选取，刷新不会换事件。每次选择后把事件 ID、次数和最近事件写入权威存档；同一地点同一天优先显示尚未发生的事件，连续两次不得出现同一事件，事件池耗尽后才按最少出现次数重新轮换。系统推荐按钮直接描述具体事情，例如检查一只漂来的封蜡木盒；只有当前地点没有合格预设事件时，才允许退回“观察当前地点的新变化”。
- **动态人物**：至少验证一名运行时人物从陌生外形与动作、名字来源、当前意图到稳定 ID、视觉锚点、人物面板和后续重逢的完整流程。
- **运行时镜头轮换**：图片分为地点建立镜头、主角第一人称现场镜头、人物反应镜头、物件/手边细节和少量第三人称动作镜头。重要对白默认从主角视点看向说话者，以人物中近景保留表情和当前地点；普通事件中，人物递来物件、现场示范、打开门窗、指向路线、桌面操作和车窗外变化都可使用第一人称。第一人称不显示主角脸、背影或肩膀，也不传玩家头像参考；正文没有明确写出主角手部时，画面不得凭空补出主角的手。第三人称不再是普通场景的无条件默认。
- **持续游玩**：作者内容负责建立世界、三条主入口、十二个区域的事件语汇、八名预设角色及五类跨区域线索；之后 Aigram 根据权威存档持续创造成年 NPC、工作、邀请、传闻和局部事件。未来生成内容必须遵守同一双语叙事、首次登场、月线中转、资源、活动线程和视觉身份合同。

### 玩家可重复进行的活动

- **当地短工**：底部行动明确显示 `90` 分钟与 `9` 枚报酬；完成后消耗 `10` 精力、获得 `9` 钱币与 `2` 风闻，并先显示具体工作与交付结果，再显示数值条。只有当前地图节点明确具备 `local-shift` 能力时，这类即时工作才可显示和执行；月线车厢等没有现场工作的地点会在扣数值前拒绝，并保留正在进行的剧情选项。同一地点同一天最多结算一次，结算后该工作选项消失；移动到新地点或进入第二天后才重新开放，强行重复提交只解释原因且不改变任何数值。精力低于 `12` 时不能开工。每份动态工作在报价时创建带稳定 ID、雇主和明确工资的权威合同；报价不入账，只有正文明确写到工作完成并按合同金额结算时才由本地 reducer 原子增加钱币。“报酬、工钱、薪水、工资”以及英文对应词只要写成玩家已经赚得、收到、领到或被交付，就同样属于完成付款，必须显示精确钱币金额并同回合入账；“下一步领取”“仍要等完成后结算”“will pay / next collect the wage”等未来计划仍是承诺，不能提前结算。正文、合同与结算不一致时整回合不得写入存档。
- **吃一顿热饭**：仅在当前节点具备 `hot-meal` 能力时可花费 `4` 钱币并恢复 `12` 精力；钱币不足或现场没有餐食时不能透支或凭空成交，拒绝后继续原剧情。
- **住一晚**：只有玩家明确选择订房、住一晚或支付房费（包括 `stay overnight`、`pay for the room` 等英文自然表达），且当前节点具备 `lodging` 能力时才算授权；本地规则先检查地点与余额，再原子扣除 `10` 钱币、写入 `lodging_secured`、恢复 `28` 精力并形成自然停止点。询问房费、寻找住宿或考虑方案只提供信息，不得自动付款或订房；“把钱全部花完”只声明预算、没有购买对象，由本地规则说明未发生交易并继续原剧情。存档保留，回来后从次日当前地点继续。
- **月线车厢休息**：在车厢内可免费恢复 `8` 精力，但时间推进且列车仍会抵达下一站；它不能替代长期住宿。
- **旅行**：跨区域先回到月台或月线车厢，再抵达目的地。普通车程花费 `3` 钱币与 `2` 精力；通行册印章只用于停运后的特殊路线。

### 三项可见数值

- **精力**：`0–100`，初始 `72`。工作、夜行和赶路消耗；吃饭与休息恢复。低于 `28` 时显示疲惫提醒，短工至少需要 `12`，普通旅行至少需要 `2`。主动恢复在任何精力值都可使用，归零只负责强制把普通行动换成恢复菜单，不是恢复功能的解锁条件。原地或故事现场的普通休息耗时 `45` 分钟恢复 `8`；“去屋里休息、选择休息、小睡”等明确行动由本地意图规则结算，询问哪里能休息、查看房价或考虑住宿不算执行。若休息动作明确写出同行者和当前区域内的具体地点，结果正文、具体场景和第一条后续选择必须保留这两项信息，不能退化成“原地坐下”的通用模板；此前仍有效的兄弟选项继续保留。放弃当前安排并前往公共休息处耗时 `120` 分钟恢复 `16`，结束当天休息到清晨耗时 `600` 分钟恢复 `36`；该动作进入真正的日终停点，清空普通行动，只保留“继续漫游”，玩家继续后才生成第二天当前地点的新场景与选择。热饭、客房和车厢分别恢复 `12 / 28 / 8`。Cartridge 的可信恢复上限为 `36`，不受模型单回合 `24` 点变更上限误截断，但最终值仍限制在 `0–100`。
- **钱币**：初始 `6`，是可立即使用的旅费，不是需要攒满的进度目标。普通车票 `3`、热饭 `4`、客房 `10`；不能透支，工作、交易和已结清委托才增加。所有支出必须来自当前玩家行动的明确授权；生成正文不能擅自替玩家购买、付款、小费或捐赠。HUD 不显示上限或进度轨，内部只保留不公开的异常保护边界。没有钱币时仍可通过帮工、步行或求助继续，但会改变时间与关系后果。
- **风闻**：`-40–100`，初始 `4`。它代表各地对玩家的公开印象，不是道德值、人物好感或恋爱值；帮助、完工和守约可提高，失约或造成公开麻烦可降低，低于 `-10` 提高危险压力，低于 `-30` 进入最高压力。它只由可见事件改变。

### 关系与角色

- 不显示单一“好感度”。关系由带来源的事件组成，例如守约、爽约、共同完成工作、保护边界、公开支持、撒谎或告别。
- 所有可发展亲密关系的角色明确为 `24+` 成年人。研修院是成人职业与魔法研修机构，不出现校园未成年人。
- 媛夕、罗温和塞莱斯特是三个开场核心角色；伊奥娜、卢克、诺尔、伊登和妮莎是旅行中逐步出现的预设长期角色。八人分别连接植物研究、月线地图、沿线演出、天气信号、渡船修理、公共照料、石坑园艺和邮路流动生活；他们不是强制攻略对象，也不会在玩家尚未到达相关地区时被预载成已认识。
- AI 可以创造新的成年 NPC。新角色第一次只作为临时偶遇存在；只有正文按“可辨认外形/动作 → 日常名字来源 → 当前意图 → 允许互动”完成正式登场，同时提交稳定角色 ID 和英文视觉身份字段后，才进入人物面板和长期关系系统。隐藏命令、对白标签、图片提示和选项不能单独完成登场。
- 运行时角色一旦固化，稳定 ID 与姓名形成不可变绑定；已有 ID 不能改名，已有姓名不能换绑新 ID。锚点任务 ID、不可变特征、承诺、关系事件和最后位置进入权威存档，职业与当前状态可以在同一身份内更新，但不能由模型静默替换成另一个人。
- `party_change` 与关系事件只能引用已经固化的角色；加入同行还必须在同一回合正文中明确发生。任一身份冲突都会拒绝相应结构化更新，而不是部分写入人物、同行或关系状态。

### 角色视觉身份实验

- 每个长期角色都有一个 `visualIdentity`：稳定角色 ID、身份状态、身份锚点任务 ID、身份版本、不可变特征、服装版本和禁止漂移项。服务返回的临时图片 URL 只在运行时解析，不作为持久身份真源。
- 首次正式登场会安排一个单人物、中近景、脸和轮廓可读的身份锚点。已有三名开场角色继续使用已审核锚点；五名新增预设角色与动态角色在首次可见登场后通过 AlterU 媒体服务生成一次 `512×640` 身份锚点，成功后只将任务 ID 固化，后续重载通过该任务解析参考图并执行 `edit`；临时图片 URL 不进入角色存档。
- 当前图片服务一次只支持一个参考。角色主导镜头只引用该角色；玩家主导镜头只引用玩家；空镜不引用。双人关系镜头使用正反打、视点镜头、背影、剪影或固定人物层，避免让两个清晰面孔同时依赖单参考生成。
- 身份生成失败不阻塞叙事。该角色仍可交谈，但在重试成功前不得继续生成无参考的清晰面部镜头。
- 垂直切片必须验证：首次登场、换地点、换光线、一次重逢、另一角色防串脸，以及一个运行时角色从临时到固化。

### 地图、中转与资源

- v2 包括 12 个稳定地图节点。新增节点分别提供：风玻璃崖的天气观测与信号维护、芦水渡村的渡船和水闸、白浪浴镇的洗衣与公共浴场、旧石坑花园的石工和梯田、云阶果园的采收与夜间授粉。
- 地点不是孤立菜单：风玻璃崖与罗温的缺失海岸地图相连；云阶果园与媛夕的植物调查相连；白浪浴镇与塞莱斯特的沿线演出相连；芦水渡村连接潮汐群岛；旧石坑花园向远灯研修院提供石材与园艺样本；妮莎的邮路可把任意两条已经发生的角色线索接起来。
- 跨地区移动必须先经过月线车厢或车站月台这一视觉与叙事锚点，再提交目的地叙事。
- `月线通行册` 有 3 枚一次性印章，可开启已发现路线的晚班车或小包厢；它是物品计量，不增加第四项 HUD 数值。

### 完成标准

- 这是持续世界，没有“看完全部 AI 文本”的穷举终点。v2 完成指：十二个区域、八名预设长期角色和五类跨区域线索进入权威世界合同；三个开场方向继续拥有作者级完整入口；新增人物保持隐藏直至合法登场；重复活动由本地规则稳定结算；AI 能在其上继续生成而不重置人物、资源、地点、活动线程或语言风格。
- 机械测试必须证明中英地图节点和 ID 完全一致、`48` 个预设事件的稳定 ID/地区/类别一致且每地恰有 `4` 个、五名新增角色初始不可见且定义完整、每人只在对应地点完成合法首次登场、跨区域线索至少连接两个不同节点，并且危险池不再只覆盖开场四种情况。事件专项还要证明：同一存档选择稳定、刷新不重抽、选择后持久化、同地连续不重复、活动危险与明确未完目标优先、事件正文与选项同一现场、自由输入主动查看仍能触发。
- 发布前必须在 `story_mode=aigram` 生产链分别试玩中文和英文的媛夕、罗温、塞莱斯特三条入口路线；对模型注入不一致回复，确认确定性主路线仍以零 `game-chat` 调用完成。另验证一条自由输入恰好调用一次模型、一条不可执行自由输入显示具体原因且零模型调用、一条精力不足拒绝、一顿饭、一次明确授权的住宿停止、一次只询问房费且余额不变、一次“支付却 +1”回复被拒绝、一次只写“赚得报酬 / received wages”但没有精确金额或结算指令的回复被拒绝、一次月线中转、一次动态角色正式登场与同行、一条隐藏角色命令、一条 ID 改名冲突，以及一次人物锚点生成后跨刷新继续复用。

### 压力、失败与恢复

- 普通探索至少持续 3 回合后才可能进入警告；5 回合内若没有压力事件则进入一次世界相关警告，解决后冷却 3 回合。
- 不使用物理战斗。压力来自末班车取消、银雨封路、雇主改约、公开误解或重叠承诺。
- 玩家的三种危险应对策略用具体动作表达：“先问清楚发生了什么”、“冒险继续原来的计划”、“先退一步，换个办法”。
- 失败产生疲惫、错过交通、钱币损失、尴尬、关系受损或路线改变；不删除存档，不强制绑定任何关系。

### 待验证实验

| 问题 | 基线 | 干预 | 可观察信号 | 通过信号 | 停止信号 | 下一步 |
|---|---|---|---|---|---|---|
| 同一 NPC 换场景后还能否被认出 | 仅重复文字外貌提示 | 固定参考图 + `edit` + 单身份镜头 | 遮住名字后的角色辨认、关键特征保留 | 4 个测试场景中至少 3 个可稳定认出且无串脸 | 连续两次重逢无法辨认或串成另一核心角色 | 改用固定人物层，不扩展内容 |
| 动态 NPC 能否从偶遇晋升为长期角色 | 模型每次重新描述 NPC | 首次正式登场后固化角色 ID 与锚点任务 ID | 重载、换地点、重逢后的档案与形象 | 存档恢复后仍使用同一 ID 与任务锚点 | 任务锚点丢失、刷新后重建或角色重复 | 修复持久化再继续 |
| 单参考限制下关系镜头是否仍有吸引力 | 两张清晰正脸的自由生成 | 正反打、视点和动作细节 | 是否能理解两人关系与当前动作 | 不依赖姓名也能说出谁在做什么 | 镜头含混或不断回退为头像摆拍 | 引入固定人物层合成 |

## 4. Controls

- 叙事正文纵向滚动；选择卡和自由输入使用 `onClick`/提交动作，不在滚动列表里使用 `onPointerDown`。
- 每回合最终采用的行动必须从 `01` 起按实际数量连续编号，同步写入正文记录，并在底部当前行动卡显示同一编号与同一文案；两处使用同一份权威选择数据，不允许模型正文与结构化命令各自维护一套选项。
- 顶部笔记本图标直接打开旅途手册的“人物关系”页；入口与文字大小、声音图标保持相同的尺寸和垂直对齐，不附加可见文字。关系页先显示关系总览，再按同行者与旅途中认识的人分组。每个人物行必须直接显示当前关系印象与共同经历数，点开后关系摘要位于人物详情首屏，完整关系记录继续向下展开。
- 每个生成回合必须把地图节点、具体场景、新任务、底部选项和新事件图作为一个原子结果提交：跨区域抵达同步更新地图节点，旅店、工坊、田舍等具体场景单独保存，不能因为仍属于同一地图节点就丢失；新任务同步更新目标，选项只能作用于当前场景，事件图必须声明并使用完全相同的具体场景。每个固定地图节点声明双语 `routeHints`，把“田野、藤架、葡萄藤”等可见语义地点稳定映射到“银叶葡萄丘”这类权威节点；用户或模型临时创造的地点也必须获得稳定 `location_id`，只保存正文公开或玩家明确命名的别名/子地点，后续新别名合并到同一节点。系统展示的可解析跨地点选项在显示时绑定 `targetLocationId`，执行后正文、HUD、图片和后续选项必须一起切换。别名重名、同一 ID 指向不同地点名或其他歧义一律拒绝猜测。纯协议地点标签缺失时由权威存档补齐；当正文、动作语义或唯一 `scene_location` 已明确证明抵达一个已知地图节点时，引擎可补齐遗漏的 `map_update`，但不能推断未知或有歧义的地点。未绑定地点或只绑定父级地图而非当前具体场景的模型图片提议直接丢弃并由本地导演重建。
- 选项数量没有“必须三个”的任务。生成回合可以显示 `1–5` 个当前真正可执行的选项：具体人物、地点、物品、机构和目标必须复用当回合正文或权威状态里的确切名词；中文不能只靠任意两个字重合放行，也不能把“具体情况、进一步消息、原因、计划”等提问修饰语误判为新人物或新地点。已知稳定人物/地点单独识别后，剩余具体对象仍须全部成立。断头路逐项过滤，其余合法项直接保留；不补占位，也不截断第四、第五个有效选项。
- 休息、吃饭、短工和消费澄清属于插入当前剧情的领域动作：结算后保留原 `decisionContext`，排除刚执行的动作，再按结算后的地点、人物和数值校验原有兄弟选项；它们不得把当前剧情替换为跨地点复用的固定工具菜单。旅行/撤离从新地点派生后续，日终/住宿进入停止点。领域动作被拒绝时零效果并保留原剧情。旧版已经保存固定五项的存档从前一场不可变选项记录恢复仍有效的兄弟分支，且迁移幂等。
- 生成结果经过一次重写后仍有支付、地点、目标、物品或其他真实状态冲突时，不显示技术错误卡；引擎拒绝不可靠结果并保留全部权威状态。若冲突来自玩家刚点击的系统跨地点选项，而该选项能由唯一 `routeHints` 目的地证明成立，则不能把它改写成“仍在原地”的断路：连续两次生成失败后只由本地 reducer 完成这条已展示路线的地点切换，并从新地点生成有依据的出口。若正文与所有状态都合法、唯一问题只是没有任何合格的新选项，则提交已经发生的结果：地点未变时优先保留上一回合仍有依据且未刚执行的行动；没有有效兄弟分支但存在明确当前目标时，直接用目标本身作为第一行动，不再包装成“追查某目标的线索”；只有没有持续事项时才使用“观察当前地点的新变化”兜底。危险回合使用 Cartridge 声明的应对方法。自由输入始终保留，不得为补数量引入新人物、地点或物品。未经证明的失败行动只保留在审计历史，在当前地点从快捷选项隔离；如果该行动后来被 Cartridge 的确定性规则、唯一语义目的地与当前合同/地点证明可执行，旧恢复存档必须重新提供这条合法路线并在本地完成。
- 可见正文一旦出现正在发生的袭击、救援、追赶、闯入或正面对峙，同一回合必须进入结构化危险阶段。此后无论玩家选择商量、观察、询问、等待还是制订计划，下一回合都必须继续写出同一批参与者与威胁；只有正文明确交代威胁如何解除，并在同回合提交危险结算，才允许回到普通剧情。活跃危险的系统选项只使用 Cartridge 声明的现场应对方法；普通回合若仍有明确目标，只显示该目标本身，不再附加可能切断现场的泛化“与同行者商量”选项。
- 系统推荐选项必须回应当前最紧迫、尚未结束的事情。仍有袭击、营救、被打断的工作、等待回答的人或正在执行的行动时，不能推荐无关工作、旅行、吃饭、休息，也不能用“商量怎么办、观察变化、等待、换个办法”代替具体行动。每个按钮应写出当前人物、物件、障碍或下一步动作；刚完成的行动及仅加“继续 / 再次 / retry”的同义重复不得立即重新推荐。若生成层没有留下任何合格选项，活动危险只能生成带当前威胁原文的应对按钮，绝不复用冲突发生前的旧选项；无危险但有明确未完目标时回到该目标，只有两者都不存在时才允许“观察当前地点的新变化”兜底。
- 三个固定开场按钮由 `opening.deterministicTurns` 按 choice id 在本地执行；玩家先自由输入询价或观察时，只要仍在开局地图节点且这些机会继续显示，它们仍由同一固定路线负责，不因场景编号不再是 `0` 而掉给模型。三条开局主路线和已经显示过的支线按钮中，成立的工作合同、固定同行、关系节点和现场询问由 `deterministicChoiceTurns` 按“当前显示按钮的精确文字 + 地点 + 稳定人物 + 必要工作状态”执行，并通过与生成回合相同的支付、地点和选项校验；Cartridge 领域动作只在本地预判为 `accepted` 时显示。相似措辞及普通自由输入不匹配该表，继续走开放叙事；能够在提交前确定缺少购买对象等条件的输入直接由精确领域规则解释，不调用模型。
- 玩家可以点击底部行动卡，也可以在自由输入框提交 `1 / 01`、`2 / 02` 直到当前最后一个选项的编号，执行对应行动；超出当前选项数量的数字和普通文字仍按自由行动处理。
- 恢复已有存档时，“继续游戏”必须定位到上一轮玩家行动与随后的剧情上下文，而不是滚动容器的物理底部；恢复后的首屏应同时看见可读剧情，底部当前行动卡保持可操作。
- 点击一个选择立即显示本地按下反馈并锁定重复提交；模型、图片和存档不能阻塞第一层反馈。
- 同行、路线、行囊和旅记通过顶部旅途手册进入；关闭后回到原阅读锚点。
- 支持中文与英文；所有按钮、标签、错误和恢复操作跟随玩家语言。
- 键盘用户可以按顺序聚焦选项、输入框和抽屉控件；移动端触控目标至少 `44×44 CSS px`。

## 5. Win / Lose Conditions

- 游戏没有传统胜利、Game Over 或唯一结局。
- 完成工作、抵达新地区、确认一段关系边界、与某人同行或分别，都是局部完成状态。
- 精力归零、钱币不足、错过交通或关系受损会改变后续路线，但不会删除进度。
- 精力归零后的普通选择、自由输入和旧存档遗留选项都必须由本地规则拦截；恢复前不能继续工作、赶路或深入探索。精力归零时若失败代价仍是扣精力，不能让无效的“继续扣零”成为唯一后果。
- 普通休息、吃饭、客房和车厢休息在危险的 `warning / confrontation` 阶段不可执行，必须显示“危险尚未解除”的世界内原因；“撤退到公共休息处”始终可用，在危险中以明确的撤退代价结束当前威胁并恢复 `16`。任何已经接受的恢复回合都禁止再叠加同回合随机危险扣除，因此休息绝不会出现净损失。
- 月线车厢、旅店休息和完成工作是自然停止点；返回时从最近权威状态继续。
- 真正结束一段关系必须由可见告别和结构化状态更新共同成立；玩家可以继续探索世界。

## 6. Sound Effects

- 所有生产音频由 Web Audio 程序合成，不依赖媒体服务生成的带声视频，也不播放隐藏视频。生成式音轨实验已证明会夹带音乐、响度不稳定且不适合循环，仅作为 QA 反例保存。
- 环境底：`19s` 双声道非重复噪声纹理，分成雨棚/玻璃的中高频层与木车厢低频层，循环边界做 `1.4s` 交叉融合；每 `7–17s` 最多出现一次轻雨滴、远轨缝或车厢沉降细节，不形成旋律。
- 普通选择：纸张擦动 + 很轻的木质票夹触点，总长不超过 `180ms`，输入后立即开始。
- 钱币增加：一枚金属触点的非整数泛音 + 木桌接触，约 `420ms`；钱币花费使用更闷、更短的衰减，不能与增加同声。
- 精力、风闻、关系、普通物品和稀有物品使用不同材质组合；不再共用同一个电子“叮”或上行音阶。
- 月线中转：相隔约 `340ms` 的两次轨缝触点 + 约 `1.05s` 低频车厢共振，只在真实地点切换时播放一次。
- 出图完成：画笔擦过冷压纸的两层带通噪声 + 极轻触点，不使用电子双音。
- 成功、失败和错误共享木质语言，以共振明暗、衰减和重复次数区分，不使用夸张胜利/失败旋律。
- 背景音乐降到环境之下，16 拍内仅有稀疏持续和声与 `2–3` 个轻触点；不能形成抢正文的短循环。
- 音频必须在用户手势后解锁、后台暂停、失败非阻塞，并提供持久静音；静音时环境、音乐和一次性反馈全部停止。
